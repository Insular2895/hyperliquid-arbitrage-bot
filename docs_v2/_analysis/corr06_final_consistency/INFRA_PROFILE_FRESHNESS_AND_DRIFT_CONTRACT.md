# InfraProfile Freshness and Drift Contract

| State | Meaning | Allowed use |
|---|---|---|
| `FRESH` | current scope and drift evidence support reuse | counterfactual research and eligible input to promotion evidence |
| `AGING` | still usable with disclosed uncertainty; material context has accumulated | research/comparison; stronger promotion review |
| `REVALIDATION_REQUIRED` | trigger makes current equivalence unproved | no material production promotion until paired refresh |
| `STALE` | validity scope/age/drift no longer supports current inference | historical sensitivity only |
| `INVALID` | corrupted, incomparable, missing critical evidence or contradicted beyond allowed use | no decision use |

No fixed monthly/calendar threshold is canonical. State is versioned and based on provider routing/host drift, Hyperliquid topology/software, peer/feed behavior, kernel/container/instance/build change, time/regime support, measured deterioration, capture anomaly and clock/Recorder validity.

Revalidation triggers include a promising provider/instance, significant Hyperliquid or feed/node change, route/network drift, latency/reliability deterioration, major bot build, unexpected capture degradation or an evidence-justified periodic review. Refresh runs a short simultaneous comparison with the current winner, retains old versions and never silently overwrites history. Larger capital/decision consequence may require stronger freshness evidence; no numeric threshold is invented.
