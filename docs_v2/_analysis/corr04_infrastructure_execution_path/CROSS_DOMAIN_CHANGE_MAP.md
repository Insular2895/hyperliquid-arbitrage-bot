# CORR-04 Cross-Domain Change Map

| Domain | Ownership after CORR-04 | Non-ownership |
|---|---|---|
| Infrastructure | profiles, benchmarks, node/feed/tuning research and promotion evidence | trading permission/formula truth |
| Data | source, time, order and epistemic provenance through linked versioned evidence | feed winner selection |
| Recorder | canonical/challenger/speculative capture, completeness/backpressure | canonical state or economic ordering |
| Risk | maps unsafe feed/node/infra evidence to permissions | speculative prediction as safety truth |
| Deployment/Security | Docker/native/network/privilege/host/node boundaries | latency-only security exceptions |
| Simulator | consumes declared feed/infra latency profile | changing Formula or actual outcome truth |
| Operations | health, lag, gaps, state age, matched lead, scheduler/runtime/profile evidence | promotion authority |
| Validation | M0–M5 evidence sufficiency, promotion/demotion scope | inventing facts/decisions |
| Execution | order/ACK/status/fill/UNKNOWN/Recovery/Reconciliation truth and single owner | dependency on speculative state |
| Formula/Economics | QF-084–QF-093 unchanged; CORR-05 audits ownership | any new priority-value formula now |

Changing canonical feed is a material cross-domain change because knowledge time, ordering, opportunities, models and Simulator calibration may change. Feed fusion remains out of scope.
